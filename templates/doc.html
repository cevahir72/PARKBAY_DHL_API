Harici sistemlerin Parkbey API servislerine erişmesi; fiyat sorgulaması, etiket ve manifest işlemlerini gerçekleştirmesi için teknik bilgiler.

1. Genel Prensip ve Yetkilendirme

API, istemcinin yalnızca gerekli iş verilerini göndermesi prensibiyle çalışır. Etiket formatlama (4×6 inç PNG), fiyat hesaplama ve diğer lojistik süreçler servisler tarafından arka planda yönetilir.

BASE_URL
https://www.parkbey.com

/api/login dışındaki tüm uç noktalarda aşağıdaki HTTP başlığı zorunludur:

HTTP Header
{
  "Authorization": "Bearer [YOUR TOKEN]"
}
Test modu: İstek gövdesine "isTestLabel": true alanını ekleyin. Bu yöntem yalnızca label/rate, label/create ve label/cancel uç noktalarında geçerlidir.

Yerel Kayıt Hatası — HTTP 500 Internal Server Error

DHL etiketi başarıyla oluşturulduğu halde etiket bilgileri Parkbey veritabanına kaydedilemezse aşağıdaki hata yanıtı döndürülür. Bu yanıt, DHL tarafında gerçek bir etiket oluşmuş olabileceğini bildirir.

Önemli: retryable alanı false olduğunda aynı istek otomatik olarak tekrar gönderilmemelidir. Tekrar gönderilmesi mükerrer etiket oluşmasına neden olabilir. İşlem, yanıttaki shipmentId ve trackingId bilgileriyle kontrol edilmelidir.
AlanTipAçıklama
errorsarrayHata ayrıntılarını içeren liste.
errors[].codestringBu durum için LabelPersistenceError değerini alır.
errors[].detailsstringDHL etiketinin oluşturulduğunu ancak yerel kaydın tamamlanamadığını açıklayan teknik mesaj.
errors[].messagestringKısa hata mesajı.
retryablebooleanİsteğin otomatik olarak tekrar gönderilip gönderilemeyeceğini belirtir; bu hata için false döner.
shipmentIdstringDHL tarafından oluşturulan gönderinin kimliği.
trackingIdstringDHL tarafından oluşturulan takip veya paket kimliği.
Örnek hata · JSON
{
  "errors": [
    {
      "code": "LabelPersistenceError",
      "details": "The DHL label was created successfully, but it could not be saved to the local system. Do not retry this request automatically.",
      "message": "Label database save failed"
    }
  ],
  "retryable": false,
  "shipmentId": "DC-JVM-1785946233589",
  "trackingId": "6100120805966856"
}
Operasyon notu: Bu hata oluştuğunda sistem dhl_create_label_db_failed aksiyon adıyla ayrı bir recovery log kaydı oluşturmaya çalışır. Recovery kaydı, DHL'de oluşturulan fakat yerel Label tablosuna kaydedilemeyen etiketlerin sonradan bulunması ve uzlaştırılması için kullanılır.

4.2 Label Oluşturma (International)

DHL Parcel International Direct (PLT) ürünü için uluslararası kargo etiketi oluşturur. Önce DHL rate alınır, 2$ eklenir. Ardından gümrük vergisi (duty) ve tax hesaplanır; etiket bu hesaplama başarılı olduktan sonra üretilir.

POST/dhl/int/label/create

İstek Gövdesi

Rate sorgusuyla aynı gövde kullanılır. Opsiyonel olarak insuranceFee gönderilebilir (verilmezse 0).

Validasyon

Gümrük hesabı için gereken veriler gönderilmeden önce alan alan doğrulanır. Eksik veya hatalı alan varsa etiket oluşturulmaz; hangi alanın nasıl düzeltileceği hata yanıtında belirtilir.

AlanKural
shipFrom.countryCode2 harfli ISO ülke kodu (örn: US)
shipTo.countryCode2 harfli ISO ülke kodu (örn: DE)
packages[].items[].hsCode6, 8 veya 10 haneli sayı; gümrük hesabında 8 haneye normalize edilir (örn: 85183000)
packages[].items[].originCountry2 harfli ISO ülke kodu (örn: US, CN)
packages[].items[].itemValue.value0'dan büyük sayı
packages[].items[].itemValue.unit3 harfli para birimi (örn: USD). Tüm kalemler aynı para birimini kullanmalıdır.
packages[].items[].quantity0'dan büyük sayı
Gizli veriler: amz_cost, my_cost, customs_value, tax ve duty bilgileri müşteriye açılmaz; yalnızca veritabanında saklanır.

Maliyet Hesabı

amz_cost = DHL ham fiyatı. my_cost = amz_cost + 2$. customs_value = duty + tax. total_cost = my_cost + customs_value.

Yanıt: International yanıtında domestic yanıtındaki totalCharge alanının yerini total_cost alır. Etiket base64 (labels[].labelData), takip numarası (labels[].trackingId, labels[].dhlPackageId) ve domestic yanıtındaki diğer alanlar aynı şekilde döner.

Gümrük Vergisi Hatası — HTTP 502

Gümrük vergisi ve tax hesaplanamazsa etiket oluşturulmaz (DHL'den ücret alınmaz). details alanı hatanın nedenini, problems alanı ise düzeltilmesi gereken istek alanlarını tek tek gösterir.

Gümrük vergisi hata örneği

    "message": "Customs tax calculation failed",
    "problems": [
      "shipFrom.countryCode must be a 2-letter ISO country code (e.g. US)",
      "packages[0].items[0].hsCode must contain 6, 8 or 10 digits",
      "packages[0].items[0].itemValue.value must be a number greater than 0"
    ]
  }]
}

4.3 Label İptal Etme (International)

Oluşturulan DHL International etiketini iptal eder (void). DHL, iptal için DELETE /shipping/v4/label/{pickup} endpoint'inde packageId veya dhlPackageId kabul eder. International (PLT) etiketlerde packageId ile "not found" (400.0000002) dönebildiği için servis otomatik olarak dhlPackageId ile tekrar dener.

POST/dhl/int/label/cancel

İstek Gövdesi

AlanTipZorunluAçıklama
shipmentIdstringEvetEtiket oluştururken dönen shipmentId (packageId / CCN).
isTestLabelbooleanOpsiyonelTest modu için true (sandbox).
dhlPackageIdstringOpsiyonelDHL'in ürettiği paket kimliği (TMUID). Verilmezse DB'deki kayıttan alınır.
pickupIdstringOpsiyonelDHL pickup hesap numarası. Verilmezse DB'deki kayıttan alınır. Test etiketlerinde (DB kaydı yoksa) zorunludur.
International Cancel Request
{
  "shipmentId": "INT-CLIENT-1703123456789-INT",
  "isTestLabel": false
}

Başarılı Yanıt — HTTP 200 OK (DHL void başarılı)

International Cancel Response
{
  "success": true,
  "message": "Label cancelled successfully",
  "shipmentId": "INT-CLIENT-1703123456789-INT",
  "dhlPackageId": "33872610208778858",
  "dhlVoided": true,
  "localCancelled": false,
  "voidedBy": "dhlPackageId"
}
voidedBy: İptalin hangi kimlikle başarıldığını gösterir (packageId veya dhlPackageId). DHL 200/204 döndüğünde DB kaydı refunded olarak işaretlenir.

Başarılı Yanıt — HTTP 200 OK (DHL void desteklemiyor / yerel iptal)

DHL Label API void işlemini ağırlıklı olarak domestic etiketler için destekler (API dokümanı: "Deleting an existing label (Domestic only)"). International (PLT) etikette packageId ve dhlPackageId ile "not found" (400.0000002) dönerse etiket yerel olarak cancelled işaretlenir. Bu durumda etiket DHL tarafında geçerli kalabilir; kullanılmamalıdır.

Local Cancel Response
{
  "success": true,
  "message": "Label cancelled locally. DHL's Label API does not support voiding international labels, so the label was not voided on DHL's side. Do not use this label.",
  "shipmentId": "INT-CLIENT-1703123456789-INT",
  "dhlPackageId": "33872610208778858",
  "dhlVoided": false,
  "localCancelled": true,
  "attempts": [
    { "identifier": "packageId", "value": "...", "statusCode": 400, "response": { } },
    { "identifier": "dhlPackageId", "value": "...", "statusCode": 400, "response": { } }
  ]
}
Önemli: dhlVoided: false ise DHL tarafında iptal gerçekleşmemiştir. Etiket manifest edilmiş veya 45 günlük iptal süresi geçmiş olabilir; DHL hesap yöneticisi ile kontrol edilmelidir. attempts alanı hangi kimliğin denendiğini ve DHL yanıtını gösterir.

Başarısız Yanıt (DHL erişim/validasyon hatası)

Hata örneği
{
  "success": false,
  "message": "DHL tarafında iptal başarısız oldu",
  "dhl_response": {
    "title": "Unauthorized or invalid pickup",
    "type": "https://api.dhlecs.com/docs/errors/403.0000001"
  },
  "attempts": [
    { "identifier": "packageId", "value": "...", "statusCode": 403, "response": { } }
  ]
}
Not: "not found" dışındaki DHL hatalarında (403 invalid pickup, 401 token vb.) DB kaydı değiştirilmez; hata doğrudan döner.
